Дата: ..20__

---

# 1. Общая информация

## 1.1 Название проекта

CRM-система для управления доставкой питьевой воды.

## 1.2 Цель проекта

Разработать мобильное приложение, позволяющее автоматизировать:

- управление клиентской базой;
- управление водителями;
- создание и контроль маршрутов;
- учет оплат и задолженностей;
- формирование отчетности;
- контроль выполнения доставок.

---

# 2. Роли пользователей

## 2.1 Администратор

Имеет полный доступ ко всем данным системы.

### Возможности:

- управление водителями;
- управление заказчиками;
- управление маршрутами;
- редактирование цен;
- просмотр результатов и отчетов;
- просмотр статистики.

---

## 2.2 Водитель

Имеет доступ только к собственным данным.

### Возможности:

- просмотр своих маршрутов;
- просмотр своих заказчиков;
- изменение статуса доставки;
- завершение заказа;
- проведение расчета заказчика.

---

# FR-4 Управление маршрутами

## Возможности администратора

- создание маршрута;
- изменение маршрута;
- удаление маршрута;
- назначение водителя;
- назначение клиентов;

---

## Маршрут содержит

- дату;
- водителя;

- статусы доставок;
- количество выполненных доставок.

---

## Статусы маршрута

| Статус | Описание |
|---------|-----------|

| CANCELLED | Отменен |

# FR-5 Работа водителя

Водитель видит только свои маршруты.

## Возможности

- просмотр маршрута;
- просмотр списка клиентов;
- изменение статуса доставки;
- завершение заказа.

---

## Статусы доставки

| Статус | Описание |
|---------|-----------|
| PENDING | Ожидает |
| ON_WAY | В пути |
| DELIVERED | Доставлено |
| FAILED | Не доставлено |
| PAID | Оплачено |

---

# FR-6 Завершение заказа

После завершения доставки водитель должен указать:

- количество доставленных бутылей;
- сумму оплаты;
- при необходимости прикрепить фотографию оплаты;
- подтвердить завершение заказа.

---

# FR-7 Расчет заказчика

Система должна автоматически рассчитывать:

- задолженность;
- предоплату;
- количество активных бутылей;
- сумму покупок.

---

# FR-8 Отчеты

Администратор должен иметь возможность просматривать:

- количество маршрутов;
- количество выполненных доставок;
- общую выручку;
- задолженность клиентов;
- статистику по водителям;
- результаты за выбранный период.

---

# 4. Пользовательские сценарии

# US-1 Создание маршрута

1. Администратор открывает экран маршрутов.
2. Нажимает «Создать маршрут».
3. Выбирает дату.
4. Выбирает водителя.
5. Выбирает заказчиков.
6. Сохраняет маршрут.

Результат:

Маршрут появляется у назначенного водителя.

---

# US-2 Завершение доставки

1. Водитель открывает заказчика.
2. Вводит количество бутылей.
3. Вводит сумму оплаты.
4. При необходимости прикрепляет фото.
5. Нажимает «Завершить».

Результат:

Информация становится доступна администратору.

# 8. Бизнес-правила

## BR-1

Маршрут считается завершенным, если все доставки завершены.

---

## BR-2

Водитель может изменять только собственные маршруты.

---

## BR-3

Администратор имеет полный доступ ко всем данным.

---

## BR-4

Задолженность рассчитывается:
Общая стоимость заказов - Общая сумма оплат

---

## BR-5

Предоплата рассчитывается:
Общая сумма оплат - Общая стоимость заказов

---

# 9. Требования к безопасности

- доступ по ролям;
- защита маршрутов других водителей;
- шифрование паролей;
- защищенное соединение;
- журналирование действий пользователей.

---

# 10. Нефункциональные требования

## Производительность

- запуск приложения не более 3 секунд;
- открытие экрана не более 1 секунды.

---

## Надежность

Приложение должно сохранять работоспособность при временном отсутствии интернета.

---

## Синхронизация

После восстановления соединения данные должны автоматически синхронизироваться.

---

## Масштабируемость

Система должна поддерживать:

- добавление новых ролей;
- расширение отчетности;
- интеграцию с внешними сервисами.

---

# 11. Push-уведомления (опционально)

## Водитель

- назначен новый маршрут;
- изменен маршрут.

## Администратор

- маршрут завершен;
- получена новая оплата.

# Критерии приемки MVP

Система считается готовой, если:

- администратор может управлять водителями;
- администратор может управлять заказчиками;
- администратор может создавать маршруты;
- водитель может выполнять доставки;
- система считает задолженность;
- доступны основные отчеты;
- данные корректно сохраняются и отображаются.
